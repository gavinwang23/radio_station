# ADS-B TCP 接收与推送 Implementation Plan

> **For agentic workers:** 使用 subagent-driven-development 分工执行，各模块先验证失败行为再实现。

**Goal:** 页面配置持久化到 MariaDB，后端解码 dump1090 30002，WebSocket 推送到 Vue/Cesium。

**Architecture:** 接收源 Repository 管理配置，TCP 接收器负责连接生命周期，解码与航空器状态独立封装。统一实时通道与前端 WebSocket 客户端供未来信号模块复用。

**Tech Stack:** Node.js 22、Express 5、mysql2、ws、Vue 2、Cesium。

**Spec:** `docs/adsb-tcp-design.md`

- [x] 解码与分帧：新增 decoder，验证 CRC、CPR 配对、过期/容量、TCP 拆包噪声。
- [x] 持久化与 TCP：新增迁移与 source Repository，验证保存失败不激活、重启恢复、断线清理和重连。
- [x] 实时通道：新增 WebSocket Hub，装配 app/server 生命周期；验证协议、客户端/快照界限、关停和源状态。
- [x] 前端：公共 HTTP 支持 PUT，配置表单与 WebSocket 客户端，验证保存/恢复/断线与旧消息隔离。
- [x] 集成：执行真实 MariaDB 建表，验证本地 TCP → 解码 → WebSocket 完整链路，运行完整测试与构建。使用临时 3001/9529 验证开发代理，结束时停止自己的临时服务器，保留用户已有 3000 服务。

独立审查指出有效消息截止、启动数据库恢复、多页面配置错配三个问题，均已修复并加入回归；前端在停用状态持续订阅，保护编辑草稿并接受后端重启后的配置版本复位。
